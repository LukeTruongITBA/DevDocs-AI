# Story 3 - Task 1: Safe metadata filtering

## Acceptance criteria and evidence

| Criterion | Implementation | Evidence |
|---|---|---|
| URL parameters are parsed into a validated filter object; raw strings never reach the vector database | `MetadataFilterParser` turns `filter=` / `filterMode=` URL parameters into an immutable `MetadataFilter` of typed values. SQL text comes only from enum constants (`FilterField`, `FilterOperator`, `EmbeddingColumn`), and every value is a JDBC bind parameter. A `filter` object in a JSON body is ignored (`@JsonIgnore`), and the controllers overwrite it. | `MetadataFilterParserTest.sqlInjectionAttemptsAreRejectedOrStayBoundValues`, `VectorSearchRepositorySqlTest`, `FilterEndpointsTest.vectorSearchIgnoresFilterSuppliedInJsonBody`, Postman #10 |
| Only whitelisted fields and operators are accepted | Fixed field→operator matrix below; values are type-checked (enum, positive integer, boolean, ISO-8601 instant, bounded string). Limits: 10 conditions, 20 `in` values, 4096 characters per parameter. | `MetadataFilterParserTest.collectsAllErrorsForUnknownFieldsOperatorsAndValues`, Postman #07 to #09 |
| An invalid filter returns 400 listing the valid fields | `FilterExceptionHandler` returns `{error, details[], syntax, validFields{field:{operators,value}}, filterModes}`. Every problem is reported at once, with user input echoed only in truncated printable form. | `FilterEndpointsTest.invalidFilterReturns400WithValidFields`, Postman #07 to #09 |
| Multi-variable filters (AND/OR) work, demonstrated by a committed Postman collection | `filterMode=AND` (default) or `OR` joins the conditions in one parenthesised group, which is ANDed with the optional `versionId` and the embedding-column predicate. | [`postman/DevDocs-Story3-Metadata-Filters.postman_collection.json`](../postman/DevDocs-Story3-Metadata-Filters.postman_collection.json): 10 requests, 24 checks, all passing against the live service on 2026-11-27 |
| A null filter falls through to the standard flow | No filter parameters yields `null`, and the existing version-scoped search runs unchanged (`versionId` still required). `appliedFilter` is `null` in the response. | `FilterEndpointsTest.nullFilterUsesStandardFlow`, `MetadataFilterParserTest.nullOrBlankFiltersFallThroughToStandardFlow`, Postman #01 |

## Syntax

```
POST /api/query/retrieve?filter=<field>:<operator>:<value>[&filter=...][&filterMode=AND|OR]
POST /api/query/answer?...      (same parameters)
POST /api/retrieval/search?...  (same parameters; body carries the embedding)
```

The value is everything after the second colon, so URLs and timestamps work unchanged. URL-encode reserved characters. `in` takes comma-separated values. When a filter is present, `versionId` in the body becomes optional; if it is supplied, it is ANDed with the filter.

| Field | SQL source | Operators | Value |
|---|---|---|---|
| `source_type` | `documents.source_type` | eq, ne, in | `STATIC` or `WEB` |
| `document_id` | `documents.id` | eq, ne, in | positive integer |
| `version_id` | `chunks.version_id` | eq, ne, in | positive integer |
| `version` | `document_versions.version_label` | eq, ne, in | string ≤ 2048 |
| `is_current` | `document_versions.is_current` | eq | `true` / `false` |
| `source` | `documents.source_uri` | eq, ne, in, prefix | string ≤ 2048 (`prefix` is LIKE-escaped) |
| `page` | `chunks.page_number`, else `metadata.page.pdf_page_number` | eq, ne, gt, gte, lt, lte, in | positive integer |
| `fetch_date` | `chunks.metadata->>'fetch_date'` | gt, gte, lt, lte | ISO-8601 instant |

`ne` is NULL-safe (`IS DISTINCT FROM`), so rows without the value count as "not equal". Filtered searches run with `SET LOCAL hnsw.iterative_scan = strict_order` (pgvector 0.8), so selective filters still fill `topK` from the HNSW index instead of returning an under-filled post-filtered page.

Example:

```powershell
curl.exe -s -X POST "http://localhost:8084/api/query/retrieve?filter=source_type:eq:WEB&filter=document_id:in:12,13" -H "Content-Type: application/json" -d '{\"query\":\"How do I configure the theme?\",\"topK\":5}'
```

## Running the collection

Import the JSON into Postman and run it, or use the dependency-free runner:

```powershell
node postman/run-collection.mjs postman/DevDocs-Story3-Metadata-Filters.postman_collection.json
```

The collection variables (`aclDocId=10`, `oracleDocId=12`, `oracleVersionId=11`, `mkdocsDocId=13`, `mkdocsVersionId=12`) match the database after the Story 1 and Story 2 ingestion of 2026-11-27. The collection is generated by `postman/build-story3-collection.mjs`.

## Logging

Filtered searches log mode, conditions, versionId, topK and result count at INFO. Rejected filters log the error list at WARN. Echoed values have control characters replaced, so they cannot forge log lines.
